# Публикация

## Коротко

- **Код** — GitHub, `beyonick/ivan_troyanovsky`, ветка `main`.
- **Хостинг** — виртуальный хостинг TimeWeb, сайт заливает GitHub Actions по SFTP.
- **Домен** — `ivantroyanovsky.nicktmsh.ru` (рег.ру), DNS смотрит на TimeWeb.
- **Медиа** (кадры и видео героя) лежат в репозитории и раздаются тем же
  хостингом. Внешних хранилищ нет.

Ветки: `main` — текущая версия (v2), `v1-previous` — прошлая, для сравнения.

---

## 1. Деплой

Виртуальный хостинг TimeWeb, сайт `ivantroyanovsky`, папка
`ivantroyanovsky/public_html`. Каждый пуш в `main` (руками или кнопкой
«Опубликовать» в админке) запускает GitHub Actions
(`.github/workflows/deploy-hosting.yml`): `.github/deploy-hosting.sh` собирает
`_deploy/` и заливает его по SFTP через `lftp mirror --delete`.

В сборку не идут `.github/`, `README.md`, `DEPLOY.md`, `admin/server.py` и локальные бэкапы. Ссылки на css и
js получают `?v=<хэш>`: nginx TimeWeb кэширует их на год, и без версии правки
из админки не дошли бы до посетителей.

Настройки в GitHub → Settings → Secrets and variables → Actions:

| Что | Где | Значение |
|---|---|---|
| `HOSTING_HOST` | Variables | SFTP-хост TimeWeb |
| `HOSTING_USER` | Variables | логин хостинга |
| `HOSTING_PASSWORD` | Secrets | пароль хостинга |
| `ADMIN_PASSWORD` | Secrets | пароль админки на сайте (придумать) |
| `HOSTING_DIR` | Variables, необязательно | по умолчанию `ivantroyanovsky/public_html` |

Пока `HOSTING_HOST` пуст, деплой собирается и пропускает заливку с
предупреждением. Собрать локально без заливки: `bash .github/deploy-hosting.sh`.

## 1а. Админка на сайте

`https://ivantroyanovsky.nicktmsh.ru/admin/` — та же админка, что локально, но
сервер у неё `admin/api.php` (PHP хостинга). `.htaccess` переводит `/api/*` на
него. Пароль — секрет `ADMIN_PASSWORD`; на хостинг попадает только соль и хэш
(`admin/admin-auth.php`). 8 неверных попыток с одного IP — пауза 15 минут.

«Сохранить» в ней сразу меняет сайт. Поэтому **хостинг главный** для
`assets/content.js`, `assets/shoots.js`, `img/` и `video/`: деплой из GitHub их не
перезаписывает и не удаляет, только докладывает отсутствующие файлы. Прежние
версии content.js/shoots.js — в `admin/backups/` на хостинге (наружу закрыта).

Перед заливкой GitHub Actions прогоняет `.github/test-admin.sh`: вход, чтение,
сохранение, загрузка и удаление кадра на встроенном сервере PHP.

## 2. Домен и HTTPS

`ivantroyanovsky.nicktmsh.ru`, DNS у рег.ру смотрит на TimeWeb. Сертификат
Let's Encrypt включается в панели TimeWeb у сайта; `.htaccess` пропускает
проверку `.well-known/acme-challenge`.

## 3. Видео героя

Файл `video/hero.webm` в репозитории, 1,3 МБ. Скрипт пробует адреса по
порядку: `heroVideo` → `heroVideoMp4` → `heroVideoFallback`
(`assets/config.js`, настройки из админки их перекрывают). Сейчас первые два
пусты, играет файл из репозитория.

Держите видео лёгким: его скачивает каждый посетитель. 10–15 секунд, не выше
1600 px по длинной стороне — кадр всё равно обрезается `cover`.

`hero.mp4` (H.264) стоит сделать: WebM не играет в Safari до 16 и в части
старых Android.

```bash
ffmpeg -i hero.webm -c:v libx264 -crf 24 -preset slow -an \
       -movflags +faststart video/hero.mp4
```

и прописать `heroVideoMp4: "video/hero.mp4"`. `+faststart` кладёт индекс в
начало файла — без него видео стартует только после полной загрузки.

## 4. Вес

Медиа v2 — около 30 МБ. Картинки грузятся лениво; страница, долистанная до
конца, — 5–7 МБ, первый экран — сотни килобайт. Админка режет кадры
в webp 1600/960/360 px.

Когда съёмок станет много, репозиторий будет расти на каждую загрузку и
хранить старые версии в истории. Тогда стоит вынести `img/s/` в объектное
хранилище (у TimeWeb есть S3) — пути в `shoots.js` поменяются на полные адреса.

## 5. Приём заявок

Форма заявки — `/zayavka.html`. Пока `SITE_CONFIG.bookingEndpoint` пуст, она
проходится целиком и показывает все состояния, **но никуда ничего не
отправляет**: в консоли остаётся предупреждение, а человек при этом видит экран
«Спасибо. Я прочитал». До публикации endpoint обязателен — иначе заявки
теряются молча.

Что нужно:

1. Приёмник, отвечающий на `POST` с JSON:

   ```json
   { "type": "love", "city": "spb", "date": "2026-10-22",
     "slot": "golden", "name": "Аня и Кирилл",
     "contact": "@annakiroff", "about": "Познакомились в очереди на Ван Гога" }
   ```

   Подойдёт Formspree, Getform или свой обработчик — что угодно, что кладёт
   письмо в почту. Ответ 2xx = успех; любой другой код или сетевая ошибка
   показывают состояние «не отправилось» со вторым путём — почтой. Введённое
   при этом не стирается.

2. В `assets/config.js`:

   ```js
   bookingEndpoint: "https://…",
   email: "ivan@troyanovsky.com"
   ```

3. Заменить плейсхолдеры `[ПОЧТА]` и `[ТЕЛЕФОН]` в `index.html`,
   `zayavka.html` и футере на реальные.

Занятые даты пока лежат в `assets/busy.js` — статический слепок в формате
будущего ответа сервера (DESIGN.md § 12). Источник (календарь, CRM или ручной
список) ещё не выбран, § 13.

## 6. Что проверить после деплоя

- Сайт открывается по HTTPS, несуществующий адрес даёт свою страницу 404.
- `/admin/` снаружи не открывается.
- Видео стартует и зацикливается в Chrome, Safari и на iPhone.
- Шапка над видео читается, после первого экрана становится чёрной.
- Наведение на кадр — приближение и наклон (§ 7.9); на телефоне эффекта нет
  и не должно быть.
- Ничего не уезжает вбок на 375px.
- `prefers-reduced-motion` (в macOS — «Уменьшение движения»): маски
  выключаются, страница остаётся читаемой.
- Заявка реально приходит на почту (§ 5), а не только показывает «Спасибо».
